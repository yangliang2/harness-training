# doc-index-builder：三道门文档分诊

你的任务：把一个"以人的视角堆放"的文档目录，分诊成"以 Agent 视角可用"的一页索引。**你只出分诊表和草稿，处置决定权在人。**

## 输入

- 文档目录（用户指定，默认 `docs/`）
- 代码根目录（用于第一道门核对，默认 repo 根）

## 对每份文档，依次过三道门

**第一道门：代码可推？**
逐段核对：这份文档的内容，能不能从当前代码直接读出来（接口签名、目录结构、配置项、流程实现）？
- 判定"是"必须带证据：列出重复陈述对应的 `文件:行号`。
- 大部分内容代码可推 → 建议处置【不入索引——代码自答】。理由写明："抄写代码的文档必然过时，是唯一会与代码打架的品种。"

**第二道门：训练已会？**
这份文档是不是通用知识——框架标准用法、工具教程、行业通识（你不看这份文档也会的内容）？
- 如实标注：此判定是**模型自评，可能误判**，必须由人复核。
- 大部分内容训练已会 → 建议处置【不入索引——训练已付费】。

**第三道门：何时读？**（只对过了前两道门的文档——决策理由、踩坑记录、版本约定、组织私有经验）
- 起草一句"什么时候该读我"（触发条件式，如"排查偶发 ANR 且主线程 trace 指向 IO 时"）。
- 核对适用边界：文档里的前提在当前代码/版本还成立吗？给出"适用版本/纪元"锚点与核对证据；无法核对的标【待人确认】。
- 起草不出"何时读"的 → 建议处置【归档】。

## 产出（两阶段，中间必须停）

**阶段一：分诊表**（输出后停下，等人逐行审批）

| 文档 | 三道门判定 | 证据 | 建议处置 | "何时读我"草稿 | 适用版本 |
|---|---|---|---|---|---|

处置只有三种：入索引 / 归档（挪 `docs/archive/`，不删除）/ 不入索引（留在原地但不上目录）。

**阶段二：按人批准后的表生成**

1. `INDEX.md`：每行 `名称 | 什么时候读我 | 适用版本 | 路径`。**全表必须一页以内**——超出时警告并要求进一步收敛，而不是默默生成长表。
2. 归档清单：需要挪入 `docs/archive/` 的文件列表（列出 `mv` 命令，**不自己执行**）。
3. 接线说明：
   - 在 CLAUDE.md 加 `@import INDEX.md`，并加一行规则："查历史经验先查 INDEX.md，按路径取正文，不要全文检索文档目录。"
   - 在 settings 的 `permissions.deny` 加 Read 规则挡住 `docs/archive/**`。

## 纪律

- 不删除任何文件；所有文件操作只列命令，由人执行。
- 每个判定必须带证据或如实标注【模型自评】【待人确认】——分诊表是给人批的，不是替人决定的。
- 历史文档"当年为真"不是入索引的理由——入索引只看三道门。
