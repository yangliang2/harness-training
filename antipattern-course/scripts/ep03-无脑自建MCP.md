### 0:20–0:50 原理立柱

【口播】
先说清一件事：AI 的"会"，只有两个来源——**要么它以前见过，要么现场有说明书可读**。两样都没有，它只能瞎猜。所以自己造工具，是一笔交易：你得到的，是一件**顺手**的工具，专为你的活设计；你付出的，是**陌生**——它从没见过这个工具，每次用都得现学。那有没有一种工具，陌生的代价照付，顺手的好处却一点没捞着？有。你们公司可能正在造。

【画面】
原理卡【可生成】两行递进："会 = 以前见过 ∪ 现场有说明书"→"自建 = 拿'顺手'换'陌生'"。

### 0:50–1:40 逐件对照（案例即原理）

【口播】
就是知识库。把那套自研工具摊开看看。搜索工具？不用造——搜文件它天生就会，熟到什么程度：Claude Code 连搜索索引都不做，官方文档原话，**"命令行工具是最省上下文的方式"**。增删改查？不用造——读文件、改文件，是它最基本的操作。历史记录？更不用造——git 天生记着每一次修改：谁改的、什么时候、为什么，一条命令全有。Karpathy 的说法是：这些都是**白送的**。你看，你造的每一件，都是它本来就会的事——代价全付了，好处一件没买到。最亏的是历史记录那格：git 白送的东西，你还得自己开发一套。

### 2:20–3:20 解法：判税三问

【口播】
往后再有人说"给 AI 写个 MCP 吧"，先过三问。**第一问：它是不是本来就会？**文件、git、grep、常见命令行能干的事，别再造一遍。知识库的正解就是这条路：文档进 git 仓库，读、写、搜、查历史，全是它的本能。别觉得这是土办法——Anthropic 自己给 AI 装知识的官方方案 Skills，就是一个装满 markdown 的文件夹。**第二问：它真不会、必须造——那就造成它能自学的样子。**首选命令行，带上 --help：它没见过你的工具，但"不会就查 --help"这个动作，它见过上亿次。接口照着主流工具的样子做——GitLab 的官方命令行，就是照着 GitHub 的抄的。**第三问：实在只能做 MCP**——远程服务、用户没有终端——那把说明当成给 AI 的提示词来写，报错信息也算说明的一部分。已经在用 Confluence、Notion？先找官方出的 server，别自己重做一个。

【画面】
三问决策树卡【可生成】逐问点亮 → 历史 spike 转录特写【实拍，spike/verify/ep04-multi-mcp/ 转录】：模型面对陌生 CLI **自发**打出 `--help` 的那一行，字幕："没人教它这么做。" → glab README "Inspiration" 节真截【真截】。

### 3:20–4:10 诚实边界（三句丑话 + 一个总账）

【口播】
三句丑话，加一笔总账。丑话一：**写知识的人得在 git 里干活，这套才成立**——企业知识库 MCP 的用户里，将近一半根本不是工程师，他们没有终端，用托管 MCP 天经地义；这集说的是工程团队自己造的那种。丑话二：**工单、订单、业务数据，别往 git 里搬**——那是数据库的活，反过来犯病一样是病；上一课那个缺陷库就该是 MCP，所以我们教你管住它的输出，而不是劝你搬家。丑话三：**文档真堆到几万篇，光靠一遍遍搜也会翻车**——但先别急着建服务，下一集就教你用一页索引解决。最后算总账：规模小，自建 MCP 拼不过文件加 git；规模真大，它又拼不过厂商的专业检索产品——**自己造知识库 MCP，不管规模大小，都轮不到它赢**。真被合规逼得必须自建？立个正经项目、配专门的人，别顺手写三个工具糊弄。

### 4:10–4:35 收尾判据

## Demo 详细步骤

### KB spike 三臂（唯一 blocking，预算 3 × N=8 × ~$0.4 ≈ $10）

- **夹具**：千篇级 markdown 知识库（= 文件方案实证获胜区间；含版本演化历史供 git log/blame 任务），同一套语料三种交付形态：
  - A：repo 直挂，原生 Read/Edit/Grep/Glob + git；
  - M0：stdio MCP server（真协议，挂 `--mcp-config`），kb_search/kb_create/kb_update/kb_get_history，description 按六成分写到合格线；
  - M1：同 server，description 按 arXiv:2602.14878 六 smell 中位数配烂（用途不清 + 参数无 intent + 无使用指引），**报错同烂**（`internal error` 一句，不递答案）。
- **任务混合（预登记，不挑食）**：增删改查、跨文档检索、历史追溯（"这条约定什么时候改的、为什么"）按固定比例混合，比例随夹具定稿写死后再跑。
- **翻车阈值（预登记，随夹具定稿量化）**：成功率差 X、工具错误次数 Y、轮次/成本差 Z——三档口径先写死再开跑，防事后找补。
- **生死判据**：M1 翻 → 叙事①；M0 输 A → 叙事②（最优先）；M0 ≈ A → 叙事③（三重成本账）。三个出口同一骨架，集子不赌 spike。
- **选条纪律**：录中位数条；--help 自发镜头选历史 spike 转录（ep04-multi-mcp，历史编号目录）。
- M2（误导档）可选加拍，先补误导流行度出处，否则只按"可构造极端情形"收窄措辞（设计档待定问题 #2）。
