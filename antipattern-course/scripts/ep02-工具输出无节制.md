## 逐字稿

### 0:00–0:20 承接 + 行为点名

【口播】
上一课我们学会了删掉不用的 MCP。但你每天在用的 MCP，也可能在偷偷拖慢、拖贵你的 Agent。你装了个缺陷查询 MCP——好用吗？好用。但你看过它一次返回多少东西吗？

【画面】
承接卡 1 秒【可生成】→ 企业内部真实 MCP 实拍【实拍，出镜面清查后】：一条查询指令 → JSON 刷屏，滚动数秒停不下来。多个内部 MCP 已挂载的画面一闪（"agent 每天背着这一排"）——**注意：不出现 `/context`/工具定义占用类画面**（那是第 1 集的病，防混淆决议）。

### 0:20–0:40 翻车实锤

【口播】
官方都在朝你弹警告——单条返回超过一万 token 它就报。这不是你运气差：Jira 官方的 MCP，单查一个 issue 就返回两万九千 token，直接撞爆上限，任务当场断掉。GitHub 官方的，一次列表返回约十万 token——而实际需要的，每条只有两三百字节。两百个字段，你用三个。

【画面】
⚠ 10k token 警告特写【实拍，企业 MCP 自然弹出为最优，缺陷夹具兜底】→ 真截两连：Atlassian 社区帖 `getJiraIssue (29544 tokens) exceeds maximum allowed tokens (25000)` 报错原文【真截】+ github-mcp-server issue #2383 标题区（带官方修复标记）【真截】。角标【可生成】：issue 编号与日期逐字可核。

### 0:40–0:55 原理立柱

【口播】
贵的不是这一次长输出——是它之后说的每一句话，都要把这些 JSON 全价重读一遍。**字节 × 轮数**，这才是你付的钱。

【画面】
轮次堆叠动画卡【可生成】：对话逐轮向下生长，每一轮都拖着前面全部 JSON 色块，色块面积累积。（串行 cache_read 385k vs 52.7k 依决议**不上卡不出词**，数字留描述区延伸阅读。）

### 0:55–1:40 A/B 对照（全集主镜头）

【口播】
同一个任务：这 6 个缺陷里哪些是 P0 还没修的，负责人是谁。左边，裸接；右边，工具和模型中间加了一层抽取。跑完看账单：成本差 __%，轮次差 __%，单次返回体积差 __%。注意——两边答案都是对的。差的从来不是模型。**工具返回又臭又长，是你的环境设计差，不是模型的病。**

【画面】
分屏实拍【实拍，缺陷夹具】：左裸接 / 右带抽取 hook，同一任务同时跑（或剪同步）。收尾三数字大字卡【可生成，占位——缺陷夹具重跑后填入】，字幕标注采样 N 与"两组正确率相同"。

### 1:40–2:50 解法一（治·抽取）

【口播】
这层东西，十五行 Python，官方管它叫 PostToolUse hook——挂在工具和模型中间：两百个字段进来，四个字段出去。装法两步：脚本放进项目，settings.json 里写一行 matcher——mcp、双下划线、你的 server 名。装完怎么知道生效了？再调一次，看单次返回的体积。判据一句话：**它每次真正用哪几个字段？** severity、status、assignee——答得上来，就抽取。

【画面】
hook 文件全貌停 3 秒【实拍】（**不逐行讲**——看懂的事交给交付物注释）→ settings.json matcher `mcp__defects__*` 特写【实拍】→ 装完重跑：单次返回 ~30KB → ~400B 对比特写【实拍】→ 验证动作【实拍】：再调一次、肉眼看体积（呼应 ep01 的 `/context` 复核——系列一致的"眼见为实"纪律）。

### 2:50–3:30 解法二（防·落盘）

【口播】
那答不上来呢？或者人家一次导出就是几百 KB？别抽了——落盘。全文写进文件，只给模型一份摘要和文件路径，它要什么，自己去文件里查。其实超过硬顶之后，harness 自己也会这么干——你顺着官方的方向，把它做完整。

【画面】
【实拍，缺陷夹具】`export_all_defects()` 一次吐 ~200KB → 对话里只剩文件引用的画面特写 → 落盘 hook 变体一屏【实拍】（全文写 payloads/ + 摘要 + "后续查询先读文件"提示）。角标【可生成】：硬顶为本版本实测约 82KB，开拍当月复核。

### 3:30–4:00 诚实边界

【口播】
三句丑话。第一，抽取是手术刀——**抽错字段，就是亲手丢信号**。这是我们抽错时的实录：模型拿不到要的字段，重试风暴，单次成本翻了十倍，最后只能诚实拒答。第二，报错不用担心被 hook 吃掉——错误内容走另一条通道，永远原样到达。第三，这些机制细节是快速迭代期的实测，以你手上的版本为准。

【画面】
B' 崩塌实录快剪【实拍，缺陷夹具重跑素材（决议：不用旧存档策展）】：重试计数攀升、成本数字、最终拒答话术，字幕如实标注采样。版本角标【可生成】。

### 4:00–4:25 收尾判据 + 反讽

【口播】
顺便说个怪事：这个能力就写在官方文档里，还是 hooks 机制里最老的一路——但全行业都在教你改 server、加网关。**最好走的路，几乎没人走。**你现在会了。判据带走：**它每次真正用哪几个字段？答得上来就抽取，答不上来就落盘。**

【画面】

## Demo 详细步骤

### 布景分工（2026-08-23 决议）

| 段落 | 布景 | 性质 |
|---|---|---|
| 开场刷屏 + 10k 警告 + 多 MCP 一排 | **企业内部真实 MCP** | 第一人称犯病率证据 |
| A/B 对照、抽取/落盘演示、B' 崩塌 | **缺陷夹具**（可控、可复现、可选条） | 数字纪律要求 |

**企业实拍红线（拍前逐项过）**：内部系统名/人名/项目代号/内网 URL/凭据字段不出镜；优先接测试库/脱敏数据，不依赖后期打码（JSON 刷屏打码易漏）；拍前与公司确认边界。若 10k 警告在企业 MCP 上无法自然弹出，该镜头改夹具拍。

### 缺陷夹具建造要点

- 协议层复用 `spike/verify/ep04-bad-mcp/` 的真 MCP 夹具（历史编号，属现第 3 集），只换数据。
- 工具面：`get_defect(id)` 单查，**无 bulk、无字段过滤参数**；`export_all_defects()` 一次 ~200KB。
- 数据面：6–8 条缺陷，单条返回 15–50KB（上百字段：changelog/评论/渲染 HTML/自定义字段）；**其中一条 >40KB 踩中 10k token 警告**（兜底镜头）。
- 任务措辞："查一下这 6 个缺陷里哪些是 P0 且未修复，列出负责人。"（真正用到 severity/status/assignee 三字段）
- 抽取 hook：matcher `mcp__defects__*`，保留 id/severity/status/assignee。

### 重跑与选条纪律

- A/B 各 N=5，卡片数字用重跑值（成本/轮次/单次体积三项 + "两组正确率相同"必须成立，不成立则停拍回查夹具）；录屏选中位数条。
- B' 崩塌（抽错字段组）：与 A/B 同批跑；若新夹具上崩塌形态不同于旧实测（重试风暴/拒答），按新形态如实呈现，不套旧叙事。
- 落盘分支与 30KB→400B 对比为确定性镜头，一条过。
- 开拍当月复核：10k/25k/落盘机制文档口径、~82KB 硬顶、matcher 写法、isError 分流（设计档待实测清单既有项）。

## 交付物文件内容

文件名：`mcp-output-toolkit/`（描述区/仓库下发，三件套一个目录）

**1. `extract-hook.py`（抽取 hook 模板）**——⏳ 源文件为 `spike/verify/ep02-mcp-extract/run_one.py` 的 EXTRACT_HOOK（脚本级实测过），待从原实验机拷贝后提炼入库，**不凭记忆重写**。模板要求：15 行级、字段清单放文件头部常量（观众只改这一处 + matcher）、注释说明"抽错字段 = 丢信号，先想清楚再列"。

**2. `spool-hook.py`（落盘变体）**——同上待提炼。行为：全文写 `payloads/<tool>-<ts>.json` + 返回摘要与路径 + "后续查询先读文件"提示。

**3. `matcher-pitfalls.md`（避坑卡，文案可先行定稿）**：

```markdown
# MCP 抽取 hook 避坑卡

## 安装两步 + 验证一步
1. hook 脚本放进项目（如 .claude/hooks/extract-hook.py）
2. settings.json 挂 PostToolUse，matcher 写 `mcp__<你的server名>__*`
3. 验证：重开会话再调一次工具，肉眼比对单次返回体积——没变小就是没生效

## 坑
- matcher 必须带 `mcp__` 前缀（只写 server 名不触发）
- 报错走 PostToolUseFailure 独立事件——错误内容永远原样到达，抽取 hook 拦不到也不需要拦
- 单次返回超硬顶（本版本实测约 82KB）时 harness 先落盘、hook 只见路径通知——抽取有效区间在硬顶之下，超大返回直接走落盘方案
- MCP 输出改写不校验 schema（比改 Bash 输出宽松——Bash 必须回对象形态）
- subagent 内 MCP 输出另有未文档化的 ~3k 上限（issue #75267，open）
- Agent SDK 的 callback hook 会静默丢弃输出改写（issue #47859）；本卡方案走命令行 hook 路径，无此问题

## Cursor 对应栏（照抄解法）
| | Claude Code | Cursor |
|---|---|---|
| 事件 | PostToolUse | postToolUse（hooks.json，官方声明兼容 CC hooks） |
| 改写字段 | `updatedToolOutput` / `updatedMCPToolOutput` | `updated_mcp_tool_output`（snake_case） |
| 覆盖面 | 全工具 | 仅 MCP 工具（本方案恰好够用） |
| 已知坑 | — | payload 无 server 身份字段（官方确认），matcher 靠 tool 名兜底 |
| 超大返回落盘 | harness 内建（超硬顶自动接管） | 无内建机制，落盘 hook 自己写文件

机制核验于 2026-08-23（research/mcp-output-tax-industry-evidence.md），以你手上版本实际为准。
```
