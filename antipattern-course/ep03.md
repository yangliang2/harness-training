# ep03 让 AI 不记错事（文档坟场）

> 状态：讨论中（场景重构 v3 方向已有共识倾向，生死 spike 未跑，见讨论记录 2026-08-21）
> 调研：research/doc-graveyard-industry-scan.md ｜ 实测：spike/verify/ep03-doc-graveyard/

## 既定事实

- **反模式**：repo 语料从不打扫——过时调研/故障复盘堆在 docs/，agent 探索时撞见。
- **原理一句**：它把你的 repo 当事实来源。
- **实测结论（2026-08-19）**：【需替代】代码与旧文档直接矛盾时 4/4 压不出喂毒——agent 站代码，还主动诊断"文档墓地"。风险收窄为"代码无法反驳"的场景。
- **调研三档**：
  - 水文区：doc rot 概念、写短点（官方 200 行红线）。
  - 值钱区：机制层——**任何权威文档都让 agent 停止验证**（新文档同样抑制验证，危害只是停查的那件事恰好为假）；能力不免疫（opus/gpt-5.4 被误导率 68–100%，surface-bench 3250 次实验）；**"可能过时"式泛警告基本无效**（恢复来自修正证据不是疑心）；"未经 eval 的文档默认是负债"。
  - 威胁项：**我们的 CLAUDE.md 两行防线（"冲突以代码为准"）正好踩"警告无效"的研究结论，必须校准**；surface-bench 未同行评审（口径"可复现实验"）。

## 讨论记录

（追加式，日期 + 决议/进展 + 理由）

- 2026-08-21：**进展：8 维评估过堂**（README 评估维度，上一轮漏用被用户纠正）。结论 7 过 1 卡——卡在维度 5（可实拍）：简单布景已证伪、新布景无实测，是 blocking 项。维度 4（信息差）为最强项：机制层（文档抑制验证/能力不免疫/警告无效证据有效）几乎无人讲。维度 2 附注：犯病率高（人人 docs/ 有尸体）≠ 发病率高（真实事故贴意外稀缺）。
- 2026-08-21：**用户质疑：文档污染是不是真的？CLAUDE.md 污染是另一场景**。拆层结论：CLAUDE.md 污染（常驻、每会话加载）证据链完整但归 ep01/主课 ep02；docs/ 语料喂毒 = 机制真（surface-bench）但发病率未证（benchmark 条件人造、第一人称事故贴稀缺、自有 spike 证伪朴素版）。
- 2026-08-21：**用户提出场景重构 v3**：真实习惯 = 把历史经验文档（写给人的：复盘/调研/wiki）放进 AI 可检索语料，并在提示词/skill 里强调参照；文档太大或冲突反而误导。三层机制支撑：①指令背书使检索从概率变指令行为、文档升级为被要求信任的权威（surface-bench：权威文档抑制验证，fresh/stale 一样）；②给人看的文档假设了会社交验证的读者（看日期/问作者/知组织变迁），喂给 AI = 抽掉验证层没补机器验证层；③冲突 → "Claude may pick one arbitrarily"（官方原文）；④太大 → 注意力稀释（归 ep02/ep06 侧，本集只讲正确性）。
- 2026-08-21：**分析：代码能反驳 = 四条件合取**（用户提出"要想一下前提"）——①文档断言对象是代码本身（经验/过程/决策类断言原理上无反驳者）②agent 真走到那份代码（存在≠在场）③文档未抑制验证（surface-bench：有文档即抑制，存在 verify-then-defer）④差异是矛盾型而非遗漏型（代码不会对"少说了"举手；此条为推理无实测）。原 spike 布景四条件全满 = 反驳最强形态，故"4/4 压不出"应改读为"四条件合满时压不出"，不是"文档无毒"。
- 2026-08-21：**用户提出失效形态关键改进**：经验文档形态 = 现象 + 怀疑方向；模块经验可能过期或打架；案例非常多时模型本身可能选错案例匹配。意义：失败点从"文档有毒"挪到**匹配层**——文档可以全是真实历史记录，病照样发；"怀疑方向"是假设不是事实断言，原理性消除代码反驳（条件 1）；最深翻车形态 = 锚定 + 虚假确认（解决了错误的问题还自我确认）。此形态天然抗过拟合（演示的是匹配层失效，非某份坏文档）。
- 2026-08-21：**过拟合担忧的对策**（用户提出）：按脊柱纪律执行——案例只当原理一个表现（选经验文档+参照指令拍透）；原理一句扛迁移（候选："它假设文档的读者会自己验证；你把读者换成了不会验证的那个"）；判据对反驳前提断裂点出三问；解法讲原则（凡喂 AI 的文档先补机器验证层）不讲单品。
- 2026-08-21：**下一步（暂缓，用户决定先存档）**：生死 spike——布景草案：小服务埋需真排查的根因 + red herring 模块（支持虚假确认）+ `docs/experience/` 6–8 条"现象→方向"案例（2 条过期指向已重写模块 / 2 条同症状冲突 / 2 条凑数 / **真因不在任何案例里**）。观察：真因命中率/轮次成本差/是否暴露冲突/是否虚假确认收工。设计红线两条（吸收 ep02 54/54 自恢复教训）：①真因必须需要真排查；②错误方向必须可虚假确认。预估 2–4 小时（夹具 1–2h + 校准 + 四组×N=5 ≈ $7–10）。
- 2026-08-21：**进展：根目录启动放大器**（用户提出）。精确表述：放大的是**遭遇率**不是中毒率——cwd 决定检索半径，默认用法 = 根目录启动 = 坟场必在半径内；症状关键词同时命中代码与案例文档 → **开场即锚定**（案例先于独立调查出现，时序是锚定的关键）；根 CLAUDE.md 必加载顺带装上指针背书。但遭遇 ≠ 中毒（旧 spike 遭遇了旧文档仍 4/4 站代码）：真实发病率 = 遭遇率 × 遭遇后被带偏率，前者由根目录默认用法拉到近 1，后者由匹配层失效决定（待 spike）。解法候选 +1 零成本防线：启动目录纪律（子目录启动/缩 scope）。
- 2026-08-21：**决议倾向：主测试改朴素形态**（用户提出）。剥掉 skill 背书、启动目录等放大器，验证最小场景："普通 repo + docs/ 一堆历史经验文档，零额外设置"。背书原来管两件事（保证遭遇/授予权威）——遭遇改由**关键词重叠**保证，适用面自动收窄到诊断/排查类任务（这本来就是经验文档的真实用途）；权威降为"检索命中里看着像答案"，锚定不靠授权靠时序。与首次 spike 的关键区别 = 文档类型：首次用的是实现断言型（"不引入 Redis"，代码直接反驳），本次用经验/方向型（"超时→怀疑连接池"，假设非断言，代码无从反驳）。**分组更新**：A=裸 repo+docs 无任何指令（主测试，压得出则主张为最强形态）/ B=无 docs 对照（难度校准）/ C=A+skill 参照指令（测背书增量：A 倒则 C 只是更快倒；A 不倒 C 倒则主张收窄为"背书是必要条件"）/ D=A+泛警告（测 H6 复现）。
- 2026-08-21：**进展：版本有效的经验污染**（用户补完场景）。核心表述：**没有一份文档在撒谎**——每份经验在它写的那个版本里都成立，污染来自时间维度被抹平（repo 里是时间轴，agent 检索到的是平面快照）。三层含义：①免疫"文档写得对不对"的审查——污染不来自文档质量；②多份不一致 = 年代不是矛盾（v1 的"超时→连接池"与 v2 的"超时→序列化"各自成立），人靠组织记忆分年代、区分层不在文档里，官方"矛盾时任意挑一个"以最无害外观出现；③"打扫也没用"——文档没错就找不到删除理由，正解同 ADR：不删、显式标注失效边界。**布景原则显式化**：fixture 里每份案例必须"历史上为真"（演示叙事："这里没有假文档，但合起来就是毒药"）。**解法细化**：状态头 → 版本锚点（"适用于哪个架构纪元/版本" + 可机检断言如"服务 X 仍是同步架构"）；doc-audit 校验对象 = "适用条件在当前代码里还成立吗"。原理一句候选再收："每份经验都对——在它写的那个版本里。人靠记忆分年代，它把不同年代的答案当成了同一代的。"诚实点：该机制叙事仍是推理链，完整链待 spike 实证；布景越写实（全部为真）结果含金量越高。
