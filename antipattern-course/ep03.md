## 既定事实（2026-08-23 重写，主题换骨版；旧版"逆分布造轮子"框架见讨论记录沿革）

- **反模式**：无脑自建 MCP——"要让 AI 用上 X"的第一反应是写个 MCP server（工具=MCP 条件反射），没先问它是不是已经会了、有没有对它更友好的形态。主案例：自建知识库 MCP（kb_search/kb_create/kb_update/kb_get_history 三件套）。
- **原理一句**："它的'会'只有两个来源——训练时见过，或运行时读到；两个都没有，它只能编。"两条推论：①熟悉决定翻不翻车（零方差下限），贴合决定跑几轮（效率上限）——两轴别混；②自建的全部收益在贴合、全部风险在分布，造轮子 = 拿贴合收益换分布税。
- **主案例结构（逐件对照）**：知识库 MCP 是零收益交易——kb_search vs Grep/Glob、kb_create/update vs Write/Edit、kb_get_history vs git log/diff/blame：贴合红利为零（一比一复刻原生能力）、分布税全额（工具名/参数/返回全在分布外）；历史那格最狠——git 免费（Karpathy 借力引用，禁称独家），自建侧还要自己造版本系统。
- **无获胜区间挤压**：小规模（团队级几百~几千篇）输给文件+git（BM25-at-scale 实证获胜区间）；中规模输给文件+git+索引（机制上被第 4 集解法覆盖；"索引撑多大规模"无一手数据，只讲机制不报数，登记 v2 实验候选）；数十万篇级检索服务确实赢，但那是厂商级产品（Cursor 自训 embedding），自研三件套更不够格——**自建 KB MCP 在任何量级都不是最优解**。活口：内网合规逼自建 = 立正经项目配专职团队，不是顺手一个 MCP。
- **实测结论**：
  - 已有（2026-08-20，历史两轮，按两轴口径重读）：help 合格自研 CLI 10/10、三工具串联 7/8 零工具错误、11.6 轮/$0.368 反超 gh 组 13.2 轮/$0.459——自研赢在贴合（活少）非熟悉；gh 零方差红利真实存在，两组零工具错误、gh 多的轮次是 base64/jq 工序不是错误。gh 接口税数据转岗诚实边界（"主流也有摩擦别迷信"），退出正片 A/B。
  - 【待跑·唯一 blocking】**KB spike 三臂**：A（markdown+git，原生工具）/ M0（KB MCP + 合格文档）/ M1（KB MCP + 中位数烂文档，烂度对标 arXiv:2602.14878 六 smell 分类学、报错同烂）。夹具千篇级（= 文件方案实证获胜区间）；任务混合预登记（查/改/历史追溯，比例定死不挑食）。生死判据预登记：M1 翻车 → 拍"56% 真实 server 的样子"；**M0 输 A → "输的是形态不是文档"实锤（最值钱镜头）**；M0 ≈ A → 主张降级为"文档合格可用，但多付开发+文档+每轮 token 三重成本换平局"，账仍负、叙事不塌。翻车阈值量化随夹具定稿一并预登记。
- **调研三档（docs-as-code-vs-kb-mcp.md，2026-08-23）**：
  - 水文区："agentic search 比 RAG 好 / Claude Code 不用 embeddings"（Cherny 名言圈内常识）；"markdown 当个人知识库"（Karpathy llm-wiki 后成大众玩法）；"MCP 工具定义吃 token"（ep01 已拍）。只当背景板。
  - 值钱区：点名"自建知识库 MCP"物种（HN 447 分 CLI-vs-MCP 帖零知识库讨论，空位实锤）；逐件对照表；税/红利双轴框架（TDS 点破过复刻结构但无经济学框架——措辞"没人给框架"，禁说"没人讲过复刻"）；MCP 规范自身的知识库空位（resources=application-driven、市面全用 model-controlled 的 tools，规范对文档场景零指导）；边界三数字本身即内容。
  - 威胁项：**"版本历史免费"被 Karpathy 逐字说过**（"You get version history, branching, and collaboration for free"）——降格为借力打法，课程增量 = 对照自建 history 工具算成本账；"纯亏"全称命题收窄限定域（Cursor +12.5% 与 BM25-at-scale 51 万篇崩盘都真实）；打击面收窄"自研自建"（Atlassian 官方 MCP 日 500 万调用、44% 用户非工程团队——hosted 是他们的正当通道）；Skills complement MCP 是官方口径，趋势可观察不可说成官方结论。
- **官方背书链（2026-08-23 一手核实）**：Claude Code best practices 原文 "CLI tools are the most context-efficient way to interact with external services" + git-history 当知识源官方示范 prompt；内置工具即文件+搜索+git、无 embeddings；Skills = markdown 文件夹进 git（2025-12-18 起开放标准 Agent Skills，OpenAI/Cursor 阵营采纳）；MCP spec 2026-07-28 对知识库场景零指导。
- **判税三问（解法）**：①它是不是已经会了？文件/git/grep/主流 CLI 覆盖 → 别造；知识库 → docs as code。②必须造（业务逻辑原生没有）→ 选它会自学的形态：CLI + --help 优先（它没见过你的工具，但见过一亿次"不会就 --help"——熟的是形态的交互协议不是你的命令）；接口照主流抄（兼容外壳，glab 照 gh 先例；企业多 MCP 拼链场景在此一句口播）。③只能 MCP（远程托管/OAuth/宿主无 shell/非工程用户）→ 文档当 prompt 写、过六成分合格线、报错也是文档；存量 Confluence/Notion 先查官方 hosted server。
- **诚实边界**：①三条正当例外——细粒度权限（页面级权限 git 给不了）/ 非工程用户（44% 数据；docs as code 前提是写知识的人在 git 工作流里）/ 事务性业务数据（工单/状态机是数据库业务，进 git 是镜像反模式；切割句：ep02 缺陷库就该是 MCP，所以那集治它的输出而不是劝搬家）。②规模边界只讲机制（盲搜 vs 导航），不报"索引撑 X 万篇"。③禁说清单：知识库 MCP 都是错的 / Skills 淘汰 MCP / 版本历史免费是我们的发现 / grep 永远够用 / 自研比 gh 强（贴合≠能力）/ 模型更会用我们的工具 / AI 熟你的 CLI（熟的是形态不是你的词）/ "56% 的 MCP 会让 agent 翻车"（56% 是描述 smell 比例）/ agentic search 比 RAG 好当新知讲。
- **与他集边界**：ep02（消费侧：治别人的坏工具）→ 本集（生产侧：别造出坏工具），承接句现成；ep04（堆料治理）承接本集"搬进 repo"钩子——"文档多了怎么办"整段甩下一集（边界即串场）；ep01 已拍工具数量的 context 税，本集不重讲 token 账。
