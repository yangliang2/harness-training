> 状态：方向定稿（2026-08-23，语料税反转叙事 + 三道门 + 多级索引；v2 重定义为索引税 A/B 待跑，通过后全集可拍）

## 既定事实（2026-08-23 重写，语料税反转版；旧版见讨论记录沿革）

- **反模式**：给 AI 的参考文档只加不理——复盘/调研/案例/wiki 全堆进 repo，以为堆得越多它学得越好（**学习错觉**：案例不进权重，只进上下文）。**隐藏层**：堆的还全是以人的视角整理的料（按组织结构/时间线排、摘要靠滚屏、假设读者会社交验证）——人自带消歧装备（看日期/认作者/组织记忆），它没有。
- **原理一句**："它不会学——文档不进它的记忆，只进它的桌面；每个会话它都是第一天上班。"（机制段金句备用："这些文档都没错——错的是读者换了。"）
- **三层结论（自有实测 + 文献三角互证）**：
  1. **效果不会更好**（正确率不动）：自有四轮 29/29 压不出中毒 + Gloaguen（context file 成功率不升，4 agent/438 任务）+ Khatri（三条件正确率零差异）——三方独立同指"喂料动成本不动正确率"。
  2. **代价一定更贵**（税无条件收）：常驻文档 +20–23% 成本（Gloaguen）；read 类占 agent 总 token 76.1%（SWE-Pruner）；信息量不变仅多分篇即 −20%（Levy，EMNLP 2025）；自有案例组 1.5–2× 轮次。
  3. **条件化危害**（正确率只在此区受伤）：测量不可得 ∧ 相似不命中密度高（surface-bench 唯一载体条件下 68–100% 被误导；Cuconasu：相似不命中加 1 篇 −25%，随机无关反而 +35%——**你精心收集的"相关案例"正是杀伤力最大的品种**）。完整命题"文档的正确率危害 = f(竞争性验证通道在场性)"为自有贡献。
- **判据（三道门漏斗）**：①代码里读得出来吗？读得出 → 不写（代码自答，抄代码的文档是唯一会与代码打架的品种）；②它训练时就会吗？会 → 不写（训练已付费）；③剩下的真金（决策理由/坑/版本约定/组织私有）：**什么时候该读你？**答得出 → 目录一行；答不出 → 躺档案。诊断问句："它每次真正用上的是哪几份？答不上来就是堆料。"
- **解法（三件套 + 接线，全官方机制）**：①doc-index-builder skill 扫 docs/ 出三道门分诊表（带证据），人只批表 → 生成 INDEX.md；②INDEX.md 一页红线（每行：名称|什么时候读我|适用版本|路径），CLAUDE.md `@import` 常驻 + "先查目录"规则行；③归档硬隔离：不入目录的挪 docs/archive/ + `permissions.deny` Read 规则（best-effort）。防复发："新文档不进目录 = 不存在。"维护：重构/升版后重跑 skill 复核"适用版本"列。
- **诚实边界**：①策划过的准确文档收益巨大（Vercel 8KB 索引 +47pp）——**劝退的是"未策划的堆"，不是文档**；②人视角机制只作税机制讲，不预言正确率（与结论 1 打架）；③"先查目录"是建议性规则，agent 可绕过自由 grep，硬隔离只有 archive 一道；④INDEX 常驻本身是税，一页红线即本集原理自用（ep01 判据复用）；⑤"训练已会"是模型自评会误判，人批表不可跳过；⑥禁说清单七条见 `research/repo-doc-hoarding-impact.md`（"案例多了一定差"禁说等）。
- **容量三前提**：人视角作机制段（≤30 秒）不作第二反模式；"先造测量再翻经验"降级进交付物清单，正片不展开；29/29 反转实录压成开场钩子（25–45 秒）。
- **与他集边界**：三道门第①问与 ep01 口诀"能从代码推出来的不用写"同源——正片一句认亲（配置层 → 语料层推广），不重讲；第②问止步于"训练已会的不用教"，不展开怎么判断（那是 ep04 裸写测试的领地）。

- 2026-08-21：**分析：代码能反驳 = 四条件合取**（用户提出"要想一下前提"）——①文档断言对象是代码本身（经验/过程/决策类断言原理上无反驳者）②agent 真走到那份代码（存在≠在场）③文档未抑制验证（surface-bench：有文档即抑制，存在 verify-then-defer）④差异是矛盾型而非遗漏型（代码不会对"少说了"举手；此条为推理无实测）。原 spike 布景四条件全满 = 反驳最强形态，故"4/4 压不出"应改读为"四条件合满时压不出"，不是"文档无毒"。
- 2026-08-21：**用户提出失效形态关键改进**：经验文档形态 = 现象 + 怀疑方向；模块经验可能过期或打架；案例非常多时模型本身可能选错案例匹配。意义：失败点从"文档有毒"挪到**匹配层**——文档可以全是真实历史记录，病照样发；"怀疑方向"是假设不是事实断言，原理性消除代码反驳（条件 1）；最深翻车形态 = 锚定 + 虚假确认（解决了错误的问题还自我确认）。此形态天然抗过拟合（演示的是匹配层失效，非某份坏文档）。
- 2026-08-21：**过拟合担忧的对策**（用户提出）：按脊柱纪律执行——案例只当原理一个表现（选经验文档+参照指令拍透）；原理一句扛迁移（候选："它假设文档的读者会自己验证；你把读者换成了不会验证的那个"）；判据对反驳前提断裂点出三问；解法讲原则（凡喂 AI 的文档先补机器验证层）不讲单品。
- 2026-08-21：**下一步（暂缓，用户决定先存档）**：生死 spike——布景草案：小服务埋需真排查的根因 + red herring 模块（支持虚假确认）+ `docs/experience/` 6–8 条"现象→方向"案例（2 条过期指向已重写模块 / 2 条同症状冲突 / 2 条凑数 / **真因不在任何案例里**）。观察：真因命中率/轮次成本差/是否暴露冲突/是否虚假确认收工。设计红线两条（吸收 ep02 54/54 自恢复教训）：①真因必须需要真排查；②错误方向必须可虚假确认。预估 2–4 小时（夹具 1–2h + 校准 + 四组×N=5 ≈ $7–10）。
- 2026-08-21：**进展：根目录启动放大器**（用户提出）。精确表述：放大的是**遭遇率**不是中毒率——cwd 决定检索半径，默认用法 = 根目录启动 = 坟场必在半径内；症状关键词同时命中代码与案例文档 → **开场即锚定**（案例先于独立调查出现，时序是锚定的关键）；根 CLAUDE.md 必加载顺带装上指针背书。但遭遇 ≠ 中毒（旧 spike 遭遇了旧文档仍 4/4 站代码）：真实发病率 = 遭遇率 × 遭遇后被带偏率，前者由根目录默认用法拉到近 1，后者由匹配层失效决定（待 spike）。解法候选 +1 零成本防线：启动目录纪律（子目录启动/缩 scope）。
- 2026-08-21：**决议倾向：主测试改朴素形态**（用户提出）。剥掉 skill 背书、启动目录等放大器，验证最小场景："普通 repo + docs/ 一堆历史经验文档，零额外设置"。背书原来管两件事（保证遭遇/授予权威）——遭遇改由**关键词重叠**保证，适用面自动收窄到诊断/排查类任务（这本来就是经验文档的真实用途）；权威降为"检索命中里看着像答案"，锚定不靠授权靠时序。与首次 spike 的关键区别 = 文档类型：首次用的是实现断言型（"不引入 Redis"，代码直接反驳），本次用经验/方向型（"超时→怀疑连接池"，假设非断言，代码无从反驳）。**分组更新**：A=裸 repo+docs 无任何指令（主测试，压得出则主张为最强形态）/ B=无 docs 对照（难度校准）/ C=A+skill 参照指令（测背书增量：A 倒则 C 只是更快倒；A 不倒 C 倒则主张收窄为"背书是必要条件"）/ D=A+泛警告（测 H6 复现）。
- 2026-08-21：**进展：版本有效的经验污染**（用户补完场景）。核心表述：**没有一份文档在撒谎**——每份经验在它写的那个版本里都成立，污染来自时间维度被抹平（repo 里是时间轴，agent 检索到的是平面快照）。三层含义：①免疫"文档写得对不对"的审查——污染不来自文档质量；②多份不一致 = 年代不是矛盾（v1 的"超时→连接池"与 v2 的"超时→序列化"各自成立），人靠组织记忆分年代、区分层不在文档里，官方"矛盾时任意挑一个"以最无害外观出现；③"打扫也没用"——文档没错就找不到删除理由，正解同 ADR：不删、显式标注失效边界。**布景原则显式化**：fixture 里每份案例必须"历史上为真"（演示叙事："这里没有假文档，但合起来就是毒药"）。**解法细化**：状态头 → 版本锚点（"适用于哪个架构纪元/版本" + 可机检断言如"服务 X 仍是同步架构"）；doc-audit 校验对象 = "适用条件在当前代码里还成立吗"。原理一句候选再收："每份经验都对——在它写的那个版本里。人靠记忆分年代，它把不同年代的答案当成了同一代的。"诚实点：该机制叙事仍是推理链，完整链待 spike 实证；布景越写实（全部为真）结果含金量越高。

- 2026-08-22：**构造失败根因提炼（三轮教训合一）**：文档从来不在关键路径上——v1 代码反驳更便宜、v2 测量更便宜，我们总给 agent 留了比"信文档"更好的路。surface-bench 能压出中毒只做对一件事：文档是信息唯一载体。→ **构造三原则**：①绕不开（必须在"信不信文档"上做决定）②竞争性验证三选一缺席（不可得/昂贵/已污染）③虚假确认闭环（agent 手头证据全说对，只有外部判据说错——下次让 bench 也站在旧世界一边）。
- 2026-08-22：**反模式再锚定（用户）**：回到候选 #15 原义"过度喂料"——习惯 = "给更多知识库/案例让模型学习"，按理会降低表现。认知差 = "学习错觉"：案例不进权重只进上下文，每轮重读重匹配，多一份相似案例 = 多一分错配面。证据侧：检索干扰/无关上下文降级（Shi 2023 等，待一手复核）+ 自家 ep01/ep02 税数据；few-shot 是同一错觉的提示词版（收益前几例饱和，many-shot 特定任务例外——口播纪律：说"相似但不命中的案例多了一定差"，不说"案例多了一定差"）。判据候选："它每次真正用上的是哪几份？答不上来就是堆料。"

- 2026-08-22：**场景关键改进（用户提出，当前候选终稿）**：**不可复现的稳定性问题 + 多触发路径 + 经验被珍视（golden case 文化）+ 无法准确 benchmark**。防弹点：测量天然缺席（非实验者删除）；"全部为真"自然成立（每份复盘记录当时真实触发路径）；犯病率最强（越难越信经验）；语料自带元教训（同症状三份复盘三个根因，症状匹配原理上不够用）。判定不靠 benchmark：植入当前真因（如异常路径连接未释放，特定下游超时触发→偶发不可复现）+ rubric 四条（诊断是否命中真因/自信宣布修好 vs 系统排除+加观测（工程正解）/是否利用"同症状多根因"做鉴别诊断/轮次成本）+ 隐藏压力测试后验兜底。解法侧新增正面英雄动作：**不可复现问题先造测量（日志/监控/灰度）再翻经验；经验给的是假设清单不是答案**。完整原理成形："它会不会被经验带偏，取决于验证在不在场——而验证不在场时，人恰好最信经验。"
