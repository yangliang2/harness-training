## 既定事实

- **反模式**：接了整表返回的 MCP / 输出从不节制的脚本，不加抽取层——每次调用几百字段灌进上下文，真正用的只有几个。
- **原理一句**：贵的不是长输出，是每轮注入上下文的字节 × 轮数——每一轮都在全价重读。
- **实测结论（2026-08-21 终版）**：【可实拍】三段实测链——
  ① 单条长输出（Bash/测试日志）：模型 54/54 自恢复，代价 +43% 轮次/+46% 成本；CC 对 exit≠0 保头截断 ~10KB 杀尾部摘要（首见：头 9/9 vs 中尾 0/18）；语义抽取（grep±上下文）9/9 且全场最便宜 > 保尾 3/9 > 保头（`ep02-tool-output` + `ep02-truncation`）。
  ② MCP 抽取 hook 完全可行，Bash 三坑在 MCP 侧全不成立：schema 三种形态都生效；hook 输入 ≥80KB 无预截断；isError 走 PostToolUseFailure 独立事件（错误内容永远原样到达）。A/B 量化（N=5）：抽取组 **-77% 成本 / -44% 轮次 / -98% 单次返回体积**，正确率 5/5；串行调用放大税（cache_read 385k vs 并行 52.7k）（`ep02-mcp-extract`）。
  ③ 落盘与硬顶（2026-08-21 补测）：落盘组四组最低成本 $0.118（全字段保真 + 本地查询零重调）；单次返回硬顶 ~82–103KB——超过则 CC 先把原件持久化，hook 只见路径通知，**抽取有效区间 <~82KB**；抽错字段崩塌实录（B' 组 5/0/0，23–32 次重试风暴，单次 $0.53，诚实拒答无幻觉）；MCP 有全量出口时模型会自己绕过抽取。
- **调研三档**：
  - 水文区：输出污染概念、安静 flag、让 agent 自己 grep（官方背书）、"成功静默"（50 年常识，cargo/Bazel/ninja 默认）。
  - 值钱区：MCP 整表返回的重复税量化（本集实测）；"摘要前置/字段抽取躲截断"的用户处方几乎没人讲；保头截断杀尾部摘要（0/18，字幕卡）。
  - 威胁项：PostToolUseFailure 拆分已固化为设计（无迁移说明）；Bash updatedToolOutput 对象形态坑（issue #68951）；>82KB harness 自动持久化旁路 hook。

- 2026-08-21：**决议：守恒量表述**——贵的不是调用次数，是每轮注入上下文的字节 × 轮数（D 组调用 4.0 次 > A 组 2.8 次但成本最低；调用次数仅在返回进上下文时是放大器，串行 385k vs 并行 52.7k）。

- 2026-08-23：**决议：主案例场景定为"缺陷查询 MCP"**（用户设想，讨论确认）。触发性质：成本翻车是机械性的（字节 × 轮数），非概率性行为翻车——必然触发，spike A/B N=5 无一逃逸。布景参数窗口（依实测③边界设计）：①MCP 只给单查接口 `get_defect(id)`，无 bulk、无字段过滤参数（烂第三方接口真实形态，逼出串行调用并堵死模型绕过口——呼应诚实边界③）；②单次返回卡 15–50KB（<~82KB 硬顶保证 hook 有效区；故意让一条查询踩过 10k token 触发官方警告，作"官方都在弹警告"镜头）；③缺陷数 5–8 个，串行税可见（cache_read 放大器）。**一景两分支**：另加 `export_all_defects()` 一次吐 ~200KB → 超硬顶 → harness 落盘接管、hook 只见路径通知 = 分诊第二条（落盘）的活演示；分诊判据从口播变成两个镜头。协议层复用 ep04-bad-mcp 夹具，只换数据。**换皮纪律**：A/B 数字（-77%/-44%/-98%）为旧夹具口径，缺陷皮夹具必须重跑才能上卡（与开拍实拍合并为一次）。

- 2026-08-23：**行业论证补强调研返回，三项定案**（`research/mcp-output-tax-industry-evidence.md`）。
  ①**行业证据段定案（维度 1 转绿）**：三机制全官方在册（10k 警告固定不可配 / 25k 默认上限 `MAX_MCP_OUTPUT_TOKENS` / 超阈值落盘换文件引用，落盘默认阈值数值文档未给——与 spike 实测 ~82KB 互补）；引用清单按报告 ③ 节执行，头部四条：官方 MCP 文档、Anthropic code execution 博客（150k→2k/98.7%）、github-mcp-server #2383（50 条 ≈400KB/~100K tokens vs 实需 200-300B/条，官方修复）、**Atlassian #17 + getJiraIssue 单查一个 issue 即 29,544 tokens 撞限——与缺陷查询主案例同构度最高，主案例场景获真实案例背书**。
  ②**信息差声明措辞定案（"几乎没人讲"改口）**：不能说没人讲过——字段两家官方文档在册、三篇低可见度文章提过机制。站得住的是**位置差 + 配方差**："全行业教你 server 侧改或加 gateway，官方写在文档里的第四条路——消费端 hook 抽取——几乎没人真的走：找不到一篇对具名第三方 server 做字段抽取的公开配方，抽取+落盘分诊结构零先例。"附赠反讽可用：`updatedMCPToolOutput` 是该机制里最老的能力、MCP 输出改写不校验 schema 比改 Bash 更顺——最好走的路最没人走。

  ④**Cursor 对应栏定调：照抄解法**：`postToolUse` + `updated_mcp_tool_output`（"For MCP tools only: replaces the tool output seen by the model"），协议兼容为官方口径；三点注明——字段名 snake_case、Cursor 只能改 MCP 输出（本案例恰好够）、payload 缺 server 身份字段（员工已确认的坑，matcher 靠 tool 名兜底）+ 落盘无 harness 内建机制 hook 自己写。
  ⑤**新增避雷项（进 matcher 避坑卡候选）**：subagent 内 MCP 输出有未文档化 3k 上限（#75267 open）；Agent SDK callback hook 的 `updatedMCPToolOutput` 被静默丢弃（#47859，命令行 hook 路径无此问题）。
