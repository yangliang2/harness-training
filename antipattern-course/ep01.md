## 既定事实

- **反模式**：MCP / skill / plugin / CLAUDE.md 只进不出，常驻即税。
- **原理一句**：常驻内容每一轮都在上下文里占位置——占的是它的注意力，也是你的钱。**具象化开场角度（2026-08-21 决议，用户提）**："官方一直在给系统提示词瘦身（CHANGELOG v2.1.154 精简提示成默认），你一不小心又全加回去了"——实测对照：空配置基线 29,249 token，挂 12 server/48 工具 +28,632，几乎翻倍（`spike/verify/ep01-mcp-tax/`）。**诚实边界**：只说"官方持续精简"（CHANGELOG 事实），不编"官方省了多少 token"的具体数字，除非开拍当月复核到官方口径。**结构定位**：原理不是开场念一遍就过去，是全集脊柱——两个案例（MCP 税 / skill 路由退化）是原理的两个表现，两个解法（/doctor 清闲置 / 归位）是原理的两个应用，收尾落成观众可迁移的判据："以后装任何新东西之前问一句：它每轮都在场吗？它挣得回这个位置吗？"
- **实测结论（2026-08-19）**：【可实拍】12 server/48 工具 = +28.6k token，线性 597/工具；/doctor 无头可跑到确认前（本机 2.1.226 满足 v2.1.206+）。
- **调研三档**：
  - 水文区：MCP 税概念（官方博客 150k→2k、98.7%）——讲了会水。
  - 值钱区：/doctor 新义（配置体检 skill）几乎无人覆盖；**skill 侧"装多了拖累路由"有官方一手证据**（2026-08-20 调研 `research/skills-overload-evidence.md`：官方设置文档 `skillListingBudgetFraction` 默认 1%、超预算丢描述只剩名字，issue #68677 实测 27 个 skill 半数被静默丢描述）。（"闲置先 disable 再 delete"2026-08-20 决议不采用——判据维持"闲置就删"，理由见讨论记录；"Tool Search 默认开启≠真的开启"同决议砍出正片。）
  - 威胁项：（均已消解：Tool Search 口径风险随砍段消解；`disabledMcpServers` vs `disabledMcpjsonServers` 易混坑随"判据不升级"不进正片。skill 侧威胁项：无"数量 vs 准确率"量化研究，禁编数字——见讨论记录。）

- 2026-08-20：**决议：翻车画面定稿**——`/context` 15 vs 3 server 对比开场；`/doctor` 表格全景放解法段；`/doctor` 在隔离 HOME 布景重演（fake-server.js 现成，避免真实用户配置出镜）；数字口径只报绝对 token + 角标注明窗口（200k 百分比走条件句口播，597×48 线性实测可核）。
- 2026-08-20：**决议：表达围绕官方指南，不自创概念**（用户）。放弃"税的大头/路由痛点"分层框架；论据结构 = 官方原话 + 自家实测数字（Anthropic 官方博客：loading all tool definitions upfront slows agents and increases costs）。"skill listing 超 1% 拖累路由"非官方口径，不作课程断言，若引用只作 /doctor 报告原话标注。——**"1% 预算非官方口径"的判断当日被新调研推翻，见下条。**
- 2026-08-20：**决议：解法补充第二条——"归位"**（用户）：项目专用的 MCP/skill 别装全局，装项目级。理由（用户）：新手犯病的典型形态是"全装全局"，全局常驻 = 每个项目每轮都付税；项目级只在对应项目付。scope 是官方一手概念（MCP 的 local/project/user、skill 的 personal/project），符合"围绕官方指南"决议；/doctor 报告表格原生带 Scope 列，镜头现成（"体检表 Scope 列全是 user 就是问题"）。官方机制细节（scope 文件位置 / 审批行为 / 迁移路径）调研核实中，结果追加进 `research/skills-overload-evidence.md`。与"闲置就删"的关系：**治 = /doctor 清闲置，防 = 装的时候问"这东西别的项目用吗"**，呼应 ep03 的治/防结构。
- 2026-08-21：**决议：原理的具象化开场角度**（用户）："官方努力减掉的 token（精简系统提示词），你一不小心又加上去了"。事实锚点：CHANGELOG v2.1.154 精简系统提示成默认（一手，主课事实清单已核）；spike 实测空配置基线 29,249 token、12 server/48 工具 +28,632（≈翻倍）。诚实边界：只说"官方持续精简"（CHANGELOG 事实），不编官方省了多少的具体数字；基线数字注明是本机后端口径。此角度同时是开场钩子：先立"官方在帮你省"，再翻"你在帮倒忙"。
- 2026-08-21：**决议：原理升级为全集脊柱，案例为理解原理服务**（用户：机械执行是更糟糕的做法，要借案例理解原理）。落地方式：原理一句不扩展成理论段（守铁律），但全集按"原理 → 案例即原理的表现 → 解法即原理的应用 → 收尾可迁移判据"组织；收尾判据定为"它每轮都在场吗？它挣得回这个位置吗？"——清单会过时，判据不会；观众遇到新型配置时自己能推。此条同时写入课程级纪律（README）。
- 2026-08-20：**"归位"机制核实完毕**（追加调研已写入 `research/skills-overload-evidence.md` 末节）。关键口径：①**`claude mcp add` 默认就是项目级（local）**，装全局（user）是主动 opt-in——本机 v2.1.235 `--help` 原文可现场演示，课程观点升级为"对齐官方默认行为"；②MCP 三档：local（仅本项目，存 `~/.claude.json` 项目条目）/ project（`.mcp.json` 签入共享，队友首次使用有审批）/ user（全局）；无 move 子命令，迁移 = remove + 重 add，注意 remove 会清 OAuth token；③skill 四级（enterprise/personal/project/plugin），归位 = `mv` 目录，但 **personal 同名压 project**——归位后必须删全局同名项（最易翻车点）；项目级 skill 无审批，与 .mcp.json 不对称；④官方无"别装全局"逐字句，表述口径定为"官方机制设计取向 + /doctor 内置迁移逻辑指向同一原则"；⑤**/doctor 有 Scope 列但不提跨 scope 迁移建议**——这正是本集信息差。
- 2026-08-20：**调研结论：skill 侧"装多了有问题"有一手证据**（后台调研，报告 `research/skills-overload-evidence.md`）。①路由退化是官方口径：官方设置文档 `skillListingBudgetFraction`（默认 0.01，超预算后"least-used skills 只剩名字，can still invoke but can't see what they do"）+ bundled doctor prompt 原文（"skill routing degrades"，本机 v2.1.235 二进制 strings 提取）+ issue #68677 用户实测（27 个 skill 约半数 description 被静默丢弃，调大预算即修复）三重印证——此前两条记录里"1% 预算非官方口径、不作断言"的保守表述作废，可按官方文档逐字讲。②常驻成本机制有官方描述：每个 skill 的 name+description 逐轮常驻（progressive disclosure 第一级），description+when_to_use 截断 1,536 字符；无"平均每 skill token"官方数字，沿用 chars/4 估算并标注 est.。③诚实边界：无"skill 数量 vs 准确率"量化曲线，禁编数字；#20143/#84666 无官方回应只能称"社区主张"；#30387（skill 不触发）是训练先验竞争、与数量无关，引用须区分；/doctor 数字为磁盘估算，演示时必须演出"`/context` 复核"这一步。④金句候选（doctor prompt 原文）："a bloated listing matters even before raw token cost does"——skill 膨胀的危害先于 token 成本，是路由质量问题。⑤与"闲置就删"决议保持一致：官方 skill 三板斧（skillOverrides / 调预算 / disable-model-invocation）不进主线，只作描述区拓展链接，正片维持单一动作。
